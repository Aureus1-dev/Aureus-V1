# Foundry Intelligence Standards

This directory contains the shared intelligence operating standards used to improve Aureus reasoning, evidence, tool selection, production quality, and learning without creating parallel authority systems.

## Core standards

### [Executive Intelligence Standard](EXECUTIVE-INTELLIGENCE-STANDARD.md)

Institution-facing intelligence standard for Founder / executive work. Defines shared context, evidence standards, question/prompt compilation, smallest-competent-skill routing, synthesis, critic/verifier roles, production preflight, and outcome learning in service of the existing Founder’s Office governance system.

### [Steward Answer Intelligence Standard](STEWARD-ANSWER-INTELLIGENCE-STANDARD.md)

Person-facing application of the same intelligence primitives. Defines how Aureus turns natural human language into an `AnswerContract`, assembles the smallest sufficient context, routes expertise/evidence/tools, compiles the internal instruction, verifies proportionally to consequence, composes the visible Steward response, transitions into governed execution when needed, and learns from outcomes without optimizing for engagement.

### [Just-in-Time Intelligence](JUST-IN-TIME-INTELLIGENCE.md)

Demand-driven research/context rule. Keep the map light; fetch deeper context, evidence, and capability information only when the active work requires it. Explicitly rejects giant speculative prompt libraries and always-on deep research.

### [Tool Intelligence Operating Model](TOOL-INTELLIGENCE-OPERATING-MODEL.md)

Governs lightweight capability awareness and targeted deep evaluation of models, software, providers, integrations, cost, reliability, licensing, privacy, and task fitness.

## Personal Steward doctrine

### [PS-001 — Personal Steward Constitution](personal-steward/PS-001-personal-steward-constitution.md)

Defines the Personal Steward’s purpose, dignity/agency boundaries, non-manipulation rules, privacy posture, and success measured by the flourishing of the person rather than frequency of interaction.

These standards do not authorize themselves. They organize intelligence and execution support inside the authority, privacy, product, and governance boundaries established elsewhere in the repository.

The active product/runtime must not become dependent on an unproductionized Foundry service merely because these standards share a directory. Runtime integration proceeds only through separately reviewed implementation work orders.
