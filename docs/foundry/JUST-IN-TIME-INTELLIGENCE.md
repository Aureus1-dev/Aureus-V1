# Just-in-Time Intelligence Operating Rule

**Status:** Governing operating clarification for `EXECUTIVE-INTELLIGENCE-STANDARD.md`  
**Principle:** Do not precompute, preload, or continuously research intelligence that has no active use. Keep the map light; deepen only when the work demands it.

## 1. Default posture

Aureus is **demand-driven, not preload-driven**.

The institution should not spend model time, research time, storage, money, or human attention building giant executive knowledge packets, competitive dossiers, creative-reference libraries, tool comparisons, or academic reviews merely because they may someday be useful.

Instead:

```text
real question / task appears
-> classify what knowledge is actually needed
-> retrieve durable Aureus context already relevant
-> check freshness / change signals
-> research only the missing or stale material
-> assemble the smallest sufficient context
-> do the work
-> verify the result
-> retain only durable lessons / provenance / useful pointers
-> allow transient research to expire
```

The goal is **deep intelligence at the moment of need without carrying the cost of deep intelligence everywhere all the time.**

## 2. What stays warm

Aureus should persist only the small amount of information that is broadly valuable or expensive to rediscover:

- mission, constitutional constraints, and authority rules;
- current institutional state and active commitments;
- decisions and their rationale;
- verified outcomes and accepted lessons;
- source provenance for durable claims;
- a lightweight source directory: where authoritative information can be obtained;
- capability metadata needed for routing: what a tool or skill is generally for;
- change signals / subscriptions / release pointers where inexpensive;
- known hazards, deprecations, contractual boundaries, and critical incompatibilities;
- indexes that let Aureus find deeper information quickly.

This is a **map**, not a warehouse of constantly refreshed research.

## 3. What stays cold until requested

Do not continuously build or refresh these unless an active task, decision, scheduled review, safety obligation, or material change requires them:

- full competitor dossiers;
- exhaustive academic literature reviews;
- large creative reference collections;
- detailed CEO / operator case-study packets;
- complete market landscapes;
- broad tool benchmark matrices;
- giant prompt libraries;
- speculative strategy analyses;
- unused executive role outputs;
- generated campaign concepts;
- detailed cross-industry analogies.

When one becomes relevant, Aureus researches it at that time using the current question as the retrieval filter.

## 4. Lightweight radar, not continuous deep research

The `Intelligence Radar` in the Executive Intelligence Standard means **cheap awareness and trigger detection**, not permanent full-depth research.

A radar event may be as small as:

- vendor release note changed;
- price changed;
- model / API deprecated;
- relevant regulation changed;
- competitor launched a material feature;
- a major research result appeared;
- Aureus encountered a new failure pattern;
- a real customer or member outcome contradicted an assumption.

The signal is stored as a pointer / candidate with timestamp and provenance. Deep analysis occurs only if the signal is relevant to active work or crosses a defined consequence threshold.

## 5. Freshness is checked on access

Do not refresh every changing fact on a timer merely because a freshness class exists.

Instead, use **refresh-on-read / refresh-on-decision** by default:

1. retrieve the relevant known fact or source pointer;
2. inspect its age and volatility;
3. if freshness matters to the current task, re-fetch or re-research it;
4. if it does not matter, do not pay the refresh cost.

Scheduled refresh is reserved for information whose stale state itself creates operational, legal, safety, security, financial, or customer risk.

## 6. Skills load only when needed

Executive skills are capabilities, not always-running personas.

For each request, Foundry / Aureus routes the **smallest competent skill set**. Examples:

- pricing decision may need CEO/Strategy + Finance + Market Research;
- production campaign may need Production House + Brand + audience research + rights verification;
- infrastructure incident may need Engineering + Security + Operations;
- a simple factual operational question may need only one skill and no executive synthesis at all.

Do not invoke the full executive team by default.

## 7. Research budget is proportional to consequence

Depth should scale with the decision:

- **Low consequence / reversible:** use existing context and a quick freshness check.
- **Moderate consequence:** targeted research from a few strong sources; inspect counter-case.
- **High consequence / expensive / difficult to reverse:** deeper multi-source research, opposing evidence, independent review, and explicit verification.

This keeps Aureus fast and cheap for ordinary work while still allowing institutional-grade depth when it matters.

## 8. Production House rule

Production House should not maintain a giant pre-generated inspiration corpus or continuously analyze every creative trend.

When a real production request arrives:

1. understand the goal and audience;
2. identify the creative questions that actually matter;
3. search current relevant references and counter-references;
4. retrieve only the applicable creative, behavioral, market, platform, and technical evidence;
5. determine which current tools best fit the job;
6. create the brief;
7. produce and test;
8. retain durable lessons from the result, not the entire transient research session unless it has continuing value.

## 9. Tool capability rule

Maintain a thin capability registry sufficient to know candidate tools and where their authoritative specifications live.

Do **not** benchmark every model against every task continuously.

At task time:

```text
work requirement
-> shortlist plausible tools from registry
-> fetch current capabilities / price / constraints for those candidates
-> use existing Aureus benchmark evidence if still applicable
-> run a targeted comparison only when the choice is consequential or uncertain
-> choose
-> record actual performance as new first-party evidence
```

Over time, Aureus becomes better informed through real use rather than through endless synthetic benchmarking.

## 10. Retention rule

After research, distinguish:

- **Durable lesson:** validated and broadly reusable -> candidate for governed Library retention.
- **Decision record:** why this specific choice was made -> retain with provenance and outcome expectation.
- **Source pointer:** useful place to re-check later -> retain cheaply.
- **Transient evidence:** useful only to this task -> expire according to policy.
- **Unproven observation:** may be kept as a candidate, clearly labeled, if future comparison has value.

Do not turn every retrieved page, prompt, model response, creative example, or intermediate thought into permanent institutional memory.

## 11. Completion test

The operating mode is correct when Aureus can answer yes to all of these:

1. Did a real task cause this research to happen?
2. Did we invoke only the skills needed for the task?
3. Did we retrieve only the evidence needed to make the work trustworthy?
4. Did we refresh volatile information because the current decision required freshness, rather than by default?
5. Did research depth match consequence and reversibility?
6. Did we keep a useful durable lesson or pointer without retaining unnecessary bulk?
7. Can the same intelligence be reconstructed later from provenance if needed?

## Governing shorthand

**Keep the map. Fetch the territory when we need it. Learn from what actually happens.**
