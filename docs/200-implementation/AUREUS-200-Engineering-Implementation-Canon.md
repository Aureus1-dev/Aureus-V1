AUREUS-200 — ENGINEERING IMPLEMENTATION CANON

Status: Canon
Authority: Engineering Architecture

---

PURPOSE

The Engineering Implementation Canon defines how the Aureus Constitution and Experience Canon are translated into production software.

It exists to ensure that every engineer, AI system, designer, and contributor implements Aureus consistently.

The purpose of this canon is not to redesign Aureus.

Its purpose is to faithfully build Aureus.

---

PRIMARY RESPONSIBILITY

The Engineering Implementation Canon exists to answer one question:

"How should Aureus be implemented?"

Its answer must always be:

Faithfully, consistently, and responsibly.

---

PHILOSOPHY

Engineering is an act of stewardship.

Every line of code teaches Aureus how to behave.

Every component teaches Aureus how to interact.

Every animation teaches Aureus how to feel.

Every implementation decision either strengthens or weakens trust.

Code is never written merely because it is technically possible.

It is written because it faithfully serves the member.

---

RELATIONSHIP TO THE CANON

The implementation hierarchy is absolute.

1. Foundation
2. Constitution
3. Experience Canon
4. Engineering Implementation Canon
5. Production Code

No implementation may contradict a higher authority.

If code conflicts with the canon, the code must change.

The canon never changes merely to justify existing code.

---

IMPLEMENTATION PRINCIPLE

Every implementation must answer three questions before it begins:

Why does this exist?

The answer must come from the Constitution.

How should it feel?

The answer must come from the Experience Canon.

How should it be built?

The answer must come from the Engineering Implementation Canon.

---

IMPLEMENTATION STANDARDS

Every implementation document shall define, at minimum:

- Purpose
- Canon references
- Functional requirements
- User experience requirements
- Visual requirements
- Accessibility requirements
- Motion requirements
- Responsive requirements
- Component architecture
- State management
- Backend dependencies
- API requirements
- Performance expectations
- Testing requirements
- Acceptance criteria
- Definition of Done

No production feature may be implemented without an implementation standard.

---

ENGINEERING PRINCIPLES

Engineers implement.

They do not reinterpret.

They do not redesign.

They do not replace established architecture without approval.

When uncertainty exists, implementation stops until the canon is clarified.

Consistency is preferred over creativity.

Faithfulness is preferred over novelty.

---

AI IMPLEMENTATION

Artificial intelligence systems are implementation partners.

AI may recommend improvements.

AI may identify defects.

AI may simplify implementation.

AI may never silently change the intended member experience.

AI must treat the canon as authoritative.

---

IMPLEMENTATION ORDER

Features should be implemented according to architectural dependency rather than convenience.

The recommended sequence is:

1. Hall
2. Steward
3. Motion & Navigation
4. Environment
5. Library
6. Steward's Study
7. Circle
8. Workshop
9. Opportunity Center
10. Garden
11. Member's Mark
12. Member Journey
13. Ceremonies & Milestones

Each implementation should build upon previously completed work.

---

CODE QUALITY

Every implementation shall:

Compile successfully.

Pass type checking.

Pass linting.

Pass automated tests.

Meet accessibility requirements.

Meet performance requirements.

Preserve backward compatibility unless an approved migration exists.

No feature is considered complete until it satisfies all acceptance criteria.

---

REVIEW

Every implementation shall be reviewed against:

- The Foundation
- The Constitution
- The Experience Canon
- This Engineering Implementation Canon

Engineering correctness alone is insufficient.

The implementation must also faithfully express the intended member experience.

---

DEFINITION OF DONE

A feature is complete only when:

It faithfully represents the canon.

It behaves consistently.

It is accessible.

It performs efficiently.

It is tested.

It has been reviewed.

It strengthens the member's trust.

If any of these conditions are not satisfied, the implementation remains incomplete.

---

THE STANDARD

The Engineering Implementation Canon fulfills its purpose only when every production feature can be traced directly from:

Principle → Constitution → Experience → Implementation → Code

There should never be uncertainty regarding why a feature exists or how it should behave.

---

NON-NEGOTIABLES

- The canon is the source of truth.
- Code exists to implement the canon.
- Member trust takes precedence over engineering convenience.
- Consistency takes precedence over novelty.
- Accessibility is mandatory.
- Performance is a feature.
- Stewardship governs every implementation decision.
